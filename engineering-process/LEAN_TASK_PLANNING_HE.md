# ASSEMBL LAB — LEAN TASK PLANNING v1.1 | נוהל עבודה חסכוני

**סטטוס:** מדיניות ביצוע רוחבית לפרויקטים הנדסיים במאגר זה. תאריך אימוץ מוצע: 2026-10-21. המיזוג ל-`main` כפוף ל-QA ולסקירת PR.

## מטרה וקדימות
לבצע כל משימה באופן המדויק, המהיר והחסכוני האפשרי, תוך **מינימום שימוש נחוץ ב-Codex**, חיסכון בעבודה חוזרת ושימוש בתוצרים קיימים — **ללא פגיעה באמינות ובאיכות**.

הנוהל חל על משימות הנדסה בכל פרויקט במאגר, אלא אם הוגדרה חריגה מפורשת ומתועדת שאינה סותרת את מדיניות האיכות. **סדר הקדימויות:** [שערי האישור](GATES.md), [תקן QA](QUALITY_STANDARD.md), דרישות בטיחות וחוזי ממשקים מאושרים, ו-[Engineering Playbook](PLAYBOOK_HE.md) גוברים על הנחיית חיסכון במסמך זה. שינוי בממשק `FROZEN` דורש Change Request; אי אפשר לעקוף G0–G5 מטעמי עלות.

## 1. ChatGPT הוא המבצע הראשי — ChatGPT First
לפני העברה ל-Codex:
- בדוק אם אפשר לבצע את המשימה, במלואה או בחלקה, **בכלים הזמינים ובאמינות הנדרשת**; אל תטען שיכולת שאינה זמינה אכן בוצעה.
- קרא קבצי מקור וגרסאות, דרישות, `BRIEF`, `STATUS`, חוזי IF, דוחות ו-PR קודמים. העדף שימוש חוזר בתוצרים קיימים; אל תשכתב CAD מאושר בשקט.
- בצע אפיון, מחקר, חישובים ניתנים לאימות, השוואה מושגית של חלופות, בחירת כיוון והכנת תנאי קבלה ותוכנית בדיקות.
- כתוב מסמכים ו-Issues, נהל תלות, בצע סקירת PR וטיפול שגרתי ב-GitHub בכלים הזמינים.
- בצע כעת את כל מה שאפשר לסיים בלי Codex; העבר לו **רק את הפער החישובי או המימושי שנותר**. לא צריך Codex כדי לכתוב תוכנית, לסכם, לבחור סדר או לייצר דוח מנהלי.

ChatGPT יכול לבדוק ראיות קיימות, אך **לא** לקרוא לבדיקת קוד/תוצר שלו עצמו `independent QA`. אם אין סוקר נפרד בעל יכולת מתאימה, השתמש ב-`INDEPENDENT_QA_PENDING`.

## 2. תיעדוף והקצאת מבצע לכל משימה
תעד:
1. **עדיפות:** `P0` קריטית (חסם בטיחותי/שער חיוני), `P1` גבוהה, `P2` בינונית, `P3` נמוכה.
2. **מבצע אפשרי:** ChatGPT / Codex / שניהם / בודק מקצועי פיזי, כשנדרש.
3. **מבצע מומלץ:** לפי זמינות כלי, איכות הראיות, מורכבות, זמן ועלות; אל תבחר Codex כברירת מחדל.
4. **ChatGPT עכשיו:** העבודה והבדיקות שניתן להשלים כבר.
5. **Codex מינימלי:** פעולה אחת מוגדרת עם קלט, פלט ותנאי קבלה, או `NOT_NEEDED`.
6. **תלויות וחסמים:** IF/Issue/Change Request/שער ונתונים חסרים.

אל תפעיל Codex לפני החלטת בעל מוצר הנדרשת לפי Playbook. `P0` אינו היתר לעקוף QA, בחינת היתכנות או בטיחות.

## 3. ביצוע בשלבים קטנים — לא לפצל באופן מלאכותי
**שלב A — ChatGPT:** השלם אפיון, החלטות שניתן לקבל, חישובים/בדיקות רלוונטיים וכל העבודה הזמינה ללא Codex. המשך עד פער אמיתי; אל תמתין להפעלת Codex רק מפני שנכתב לו Issue.

**שלב B1 — Codex, בדיקת היתכנות מינימלית (רק אם נחוצה):** בצע B1 **רק** כאשר יש אי-ודאות חישובית/גאומטרית מהותית ותשובת GO/REVISE/NO-GO עשויה למנוע מימוש שגוי ויקר. בדוק את ההשערה המינימלית, עם גבולות תוקף ברורים:
- `GO`: ישימות **בתחום שהוכח בלבד**; אין אישור אוטומטי ל-B2.
- `REVISE`: נדרש שינוי או החלטה לפני מימוש.
- `NO-GO`: ההשערה שנבחנה אינה ישימה, לא בהכרח כל חלופה אפשרית.

עצור לאחר B1 והחזר ל-ChatGPT לבדיקת ראיות ולהחלטה לפני B2. **אפשר לדלג על B1** במשימה מוכרת, פשוטה או מאומתת מראש; אם נדרשת רק קריאת Codex ממוקדת אחת, אין לפצל לשתי קריאות בלי הצדקה.

**שלב B2 — Codex, מימוש ממוקד (כאשר באמת נדרש):** עבודה רק על חלופה אחת נבחרת, תוך שימוש בקוד ובמודל הפרמטרי הקיים. הפק את **המינימום שמאפשר הוכחה ומסירה**, ולא אוסף אוטומטי של הדמיות/חלופות. בדוק ממשקים שהשתנו ותלויות מושפעות, לפי QA ושער הפרויקט. אל תשנה חלק מאושר ללא Change Request מתועד.

**שלב C — ChatGPT:** סקור את מקור המימוש, קובצי היצוא, הממשקים והראיות; דרוש תיקון ממוקד בעת הצורך; פעל לפי [שערי האישור](GATES.md) ו-[תקן QA](QUALITY_STANDARD.md). כשהמימוש נוצר על ידי Codex, סקירה נפרדת אמיתית עשויה לשמש QA עצמאי **רק אם** נבחנו ראיות בפועל באופן בלתי תלוי ולא הועתקה תוצאת המבצע. כש-ChatGPT יצר את התוצר, דרוש סוקר עצמאי נוסף לאותו תחום.

## 4. מדיניות בדיקות לפי סיכון
- בדוק כל שינוי ואת **כל הממשקים המושפעים ישירות או בעקיפין**, לפי מפת תלות וסיכון.
- בדיקות שליליות נדרשות כאשר תקן QA או טענת ההוכחה מחייבים אותן; לא לפי מכסת בדיקות שרירותית.
- אין לבצע אוטומטית רגרסיה מלאה לרכיבים בלתי משתנים ובלתי תלויים. כן בצע רגרסיה רחבה לאחר שינוי תשתית/חוזה משותף, בשערי G2a/G2b/G4, או כשסיכון מחייב.
- שמור רישום בדיקות ייחודיות, לוגים, כישלונות ראשוניים/סופיים, תיקונים, מחזורי ריצה וכל `NOT_RUN` מהותי.
- בדיקות גאומטריה/חיבורי DXF, מסלולי הכנסה ב-3D, חומר/kerf בפועל ובדיקות פיזיות הן ראיות **נפרדות**; אין להמיר אחת באחרת.
- `QA >= 90/100` וללא חוסם `CRITICAL` בתחום ה-PR נדרשים לפי המדיניות; ציון אינו מחליף G3/G4.

## 5. צמצום תוצרים חכם
אל תיצור באופן אוטומטי שלוש חלופות CAD מלאות, גלריות הדמיות חוזרות, דוחות כפולים, קבצים שלא השתנו או מסמכים נפרדים כשמסמך קומפקטי מספק את אותה עקיבות.
**חריג חובה:** אל תחסוך ב-BOM/IF, תוצרי מקור/יצוא נדרשים, תוכנית הרכבה, ראיות בדיקה, לוגים, QA עצמאי, דיווח כשלים ותיעוד חתימות/אישורי שחרור הנדרשים לשער הרלוונטי. דוח קצר רשאי להפנות לראיות קיימות עם SHA במקום להעתיקן.

## 6. עצירה מוקדמת ותיקון שגרתי
**עצור והסלם** במקרה של סתירה במפרט `FROZEN`, כשל גאומטרי/מסלול הכנסה שחוסם את ההוכחה המבוקשת, שינוי מהותי בצורה/תפקוד/בטיחות, ראיות חסרות לשער או שינוי שלא אושר. דווח מה הוכח, מה נכשל, מה נשאר פתוח ומהי ההחלטה הנדרשת. אין ליצור קבצים נוספים רק כדי להראות פעילות.

**מותר לתקן ולבדוק מחדש ללא סבב אישור** שגיאת קוד/גאומטריה מקומית ששינוי בה אינו נוגע לממשק מאושר, להיקף המשימה או לרמת הסיכון. חובה לתעד כשל, תיקון ומספר מחזורי בדיקה; הישנות או התרחבות הבעיה מחייבת סקירה מחדש.

## 7. רמת חשיבה — המלצה ולא שליטה בהגדרות המשתמש
כאשר תצורת המוצר מאפשרת בחירת מאמץ חשיבה: `Instant / Medium` לאפיון פשוט ובדיקות בסיסיות; `High` לתכנון הנדסי קשה ואינטגרציה; `Extra High` רק כשסיכון ומורכבות מצדיקים. אין להניח ש-ChatGPT יכול לשנות בעצמו את ההגדרה בפועל. בחירת מודל אינה במקום בקרת איכות.

## 8. GitHub וממשל תצורה
`Issue → ChatGPT-first scoping → targeted execution → tests → independent QA → PR → lead review → approved merge / repair`.
השתמש בענף ייעודי, בשמות חלקים וממשקי IF יציבים וב-Change Request לשינוי מאושר. Codex אינו ממזג PR של עצמו; **אין מיזוג אוטומטי**. `DESIGN_ONLY` אינו מאשר ייצור, ושום PASS ב-CAD לא מקדם G3 או G4 בלי ראיות פיזיות/שחרור.

## 9. דוח מצב קצר לאחר כל שלב
דווח באופן תמציתי:
1. מה בוצע (כולל SHA/PR/גרסה כשקיימים).
2. מה נבדק, כמה מקרים ייחודיים ומה התוצאה.
3. כישלונות, מספר תיקונים, `NOT_RUN`, חסמים וממשקים פתוחים.
4. המשימה הבאה והעדיפות שלה.
5. מי **יכול** לבצע ומי **מומלץ** שיבצע.
6. האם נדרש Codex — ואם כן, רק הפעולה המינימלית.

אפשר לקשר לדוחות המסירה/QA הקיימים במקום להעתיק תוכן, **בתנאי שכל ראיות החובה נשארות נגישות**.

## 10. כלל מחייב
**ChatGPT ממשיך בעצמו בכל משימה שניתן לבצע במדויק ובבטחה בכליו, עד לחסם אמיתי המצריך Codex או בודק ייעודי.** מעבירים רק את החלק ההכרחי שנותר; נמנעים מהפעלה לשם תוכנית, סיכום או דוח שניתן להכין בצ'אט. **מינימום עבודה כפולה — בלי קיצורי דרך בבדיקות, בשינויי תכן ובשערי האיכות.**
