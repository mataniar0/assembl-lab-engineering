# CTB-000 — הוראות עבודה לסוכני Codex

## לפני תחילת משימה
1. קרא `SPEC_HE.md`, `DECISIONS.md`, `CTB-000_parameters.json`, `CTB-000_interfaces.json`, `CTB-000_open_issues.csv`.
2. הצג רשימת מזהי IF שהמשימה מממשת, ותלויות. אל תתחיל רכיב תלוי אם הממשק המקושר עדיין OPEN.
3. שמור מערכת צירים XYZ ואותו חלק מקומי (`r,t,z`). כל המידות ממ״מ.
4. עבור Nesting השתמש רק בלוח עומד: **גובה 800 × רוחב 440 מ״מ**; בציר 2D: X אופקי עד 440, Y אנכי עד 800. אין להשתמש במידה הקודמת 900×440.
5. סדר שדה התאימות `stock_sheet_mm` הוא `[height,width]`; העדף תמיד את שני שדות המידה המפורשים.
6. התחל מענף Git עצמאי. אין לערוך אותו חלק בשני ענפים מקבילים ללא תיאום.

## מסירה לכל חלק
- תיאור חלק + BOM.
- קוד פרמטרי ומקור הגאומטריה (single source of truth).
- קובץ DXF ו־SVG (מסומנים DESIGN_ONLY עד אישור ייצור), תצוגת PNG עם מידות.
- JSON תוצאת ממשקים לכל IF נדרש: PASS_CAD, FAIL, BLOCKED, או PENDING_PHYSICAL.
- דוח QA: כמות בדיקות, כמות כשלים, מספר תיקונים, מספר מחזורי בדיקה, שינויים במידות.
- טבלת Fit/Slot מותנית ב־kerf ועובי חומר מדוד; אין לייצר סבילות נומינלית כאילו נמדדה.
- Pull Request לביקורת, ללא merge אוטומטי.

## מדיניות אי־ודאות
- פער בנתון נעול => BLOCKED + Change Request.
- פער בממשק זמני => הצע חלופות והשפעה על שאר החלקים; אל תשנה חוזה משותף בשקט.
- תמונת AI אינה ראיה להתאמה מכנית.
- בדיקת DXF אינה בדיקת עומס או יציבות.
- ניסויי מכונה/חומר והפעלה פיזית יבוצעו רק בסביבה מפוקחת ומתאימה; אין להציגם כבוצעו בלי מדידה אמיתית.
